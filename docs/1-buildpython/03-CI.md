# CI

KeyRGB uses GitHub Actions to run `buildpython` as the main validation entrypoint.

## Quality and runtime workflows

`.github/workflows/ci.yml` has two jobs:

1. **Quality Gate** on Python 3.12:

   ```bash
   sudo apt-get install -y shellcheck
   python -m buildpython --profile=ci
   ```

   Then it builds a wheel and smokes nested reference-default resources from the
   installed artifact.

2. **Runtime Matrix** on Python 3.10, 3.11, 3.12, 3.13, and 3.14 after quality passes:

   ```bash
   python -m buildpython --run-steps="Compile,Import Validation,Import Scan,Pip Check,Pytest,Coverage"
   ```

Type Check keeps the 3.10 language floor (`[tool.mypy] python_version = "3.10"`)
and `requires-python` stays `>=3.10`: CI tests newer runtimes without raising
the minimum supported version.

The current `ci` profile includes:

- `Compile`
- `Ruff`
- `Ruff Format`
- `Import Validation`
- `Import Scan`
- `Pip Check`
- `Type Check`
- `Pytest`
- `Coverage`
- `Exception Transparency`
- `Code Hygiene`
- `Code Markers`
- `File Size`
- `LOC Check`
- `Dead Code`
- `ShellCheck`
- `Architecture Validation`
- `Repo Validation`

Buildpython forces hardware tests off (`KEYRGB_HW_TESTS=0`).

Buildpython's default compact presentation applies both locally and in GitHub
Actions. Checks print concise outcomes and factual counts; coverage prints its
measured percentage. Relevant checks show the same per-finding penalty health bars
locally and in CI; see [health scoring](06-Health-scoring.md). Raw command output is kept in the canonical
`buildlog/keyrgb/step-*.log` files instead of being dumped into the Actions
console. Failed CI and release jobs upload `buildlog/keyrgb/` as a seven-day
artifact. Use `--verbose` to restore raw terminal output when debugging.

There is no CI AppImage job. Use `--with-appimage` locally on top of another
profile, or run the release workflow.

## Dependency audit

Both CI quality and release jobs run a pip-audit supply-chain check after
`.[dev]` installation and before buildpython. Reproduce it locally with:

```bash
.venv/bin/python scripts/dependency_audit.py --project-dir .
```

Exit semantics: 0 clean, 1 findings, 2 tool/advisory/resolution failure. It audits
runtime requirements declared in pyproject rather than arbitrary ambient packages.

## Release workflow

Tagged releases (`.github/workflows/release.yml`) use:

```bash
python -m buildpython --profile=release
```

The current `release` profile is the `ci` quality set plus `AppImage` and
`AppImage Smoke`. The resulting AppImage and SHA-256 sidecar are uploaded to
the GitHub Release.

Release artifacts are built on **Ubuntu 22.04**, not the floating
`ubuntu-latest`, with Python **3.10** to match Jammy's `python3-gi` extension ABI.
Python is bundled; users do not need to install that Python version. Every
bundled ELF (including native wheels) is checked against a **glibc 2.35** ceiling
before packaging. Indicator and dbusmenu libraries copied from a newer host are
replaced with pinned Ubuntu 22.04 packages before that check. Python, wheels,
and any other bundled ELF still have to meet the ceiling; do not bundle glibc
or its loader to evade the check. The indicator fallback needs `ar` and `zstd`.

The default Docker smoke matrix uses Ubuntu 22.04 and 24.04. It first checks
minimal Tcl/Tk/import/diagnostics paths, then installs only the host GTK/GLib and
display/session stack and tests Tk window creation, the bundled GI/indicator
backend, and the actual `AppRun --diagnostics` launcher. It does not install host
Python GI or indicator/dbusmenu packages, which would hide missing bundled
components. `KEYRGB_APPIMAGE_SMOKE_IMAGE` still selects a single custom image for
local debugging. GTK/GLib/font libraries remain host desktop dependencies to
avoid mixing incompatible desktop stacks. Udev permissions are separate system
integration, not bundled shared-library dependencies.

## Practical debugging

When CI fails, reproduce locally with the same profile and inspect `buildlog/keyrgb/`, especially:

- the failing `step-*.log`
- `build-summary.md`
- `debt-index.md`
- any structured report tied to the failing debt step
